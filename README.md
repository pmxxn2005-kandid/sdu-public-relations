# เว็บไซต์กองประชาสัมพันธ์ มหาวิทยาลัยสวนดุสิต

เว็บไซต์และ Admin ที่ทำงานจริงด้วย PHP + PDO รองรับ MySQL และ SQLite สำหรับทดสอบในเครื่อง โดยใช้ดีไซน์สีฟ้า–ขาว–ดำและเมนู **บุคลากร** ตามที่ตกลง

## เปิดใช้งานในเครื่อง

ต้องมี PHP 8.2 ขึ้นไป พร้อม PDO, pdo_sqlite, pdo_mysql, mbstring, fileinfo และ GD ที่รองรับ WebP

```sh
cp .env.example .env
php bin/setup.php
php bin/seed.php
php -d upload_max_filesize=10M -d post_max_size=12M -d max_input_vars=2000 -S 127.0.0.1:8080 -t public public/router.php
```

- เว็บไซต์: http://127.0.0.1:8080
- Admin: http://127.0.0.1:8080/admin
- บัญชีผู้ดูแลเริ่มต้น: ดู `storage/setup-credentials.txt` ซึ่งสร้างรหัสผ่านสุ่มเมื่อ setup ครั้งแรกในโหมด local และเก็บนอก public
- `seed.php` เป็นตัวเลือก สร้างข้อมูลตัวอย่างเฉพาะ local และไม่เขียนทับเนื้อหาที่มีอยู่
- ครั้งนี้ตั้งฐานข้อมูล SQLite และข้อมูลตัวอย่างไว้แล้ว สามารถใช้คำสั่งเปิดเซิร์ฟเวอร์ได้ทันที

ไม่ต้องติดตั้ง npm เพื่อรันเว็บไซต์ ใช้ npm เฉพาะเครื่องมือทดสอบเบราว์เซอร์

## เปลี่ยนไปใช้ MySQL

1. สร้างฐานข้อมูลชื่อ `sdu_pr` โดยใช้ `utf8mb4` และบัญชีที่มีสิทธิ์เฉพาะฐานข้อมูลนี้
2. เปลี่ยน `.env` ดังตัวอย่าง โดยกรอกค่าจริงของเซิร์ฟเวอร์และรหัสผ่าน

```dotenv
APP_ENV=production
APP_URL=https://your-domain.example
DB_DRIVER=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=sdu_pr
DB_USERNAME=sdu_pr
DB_PASSWORD=your-database-password
ADMIN_EMAIL=your-admin-email@example.com
ADMIN_PASSWORD=your-6-to-12-character-password
SESSION_SECURE=1
```

3. รัน `php bin/setup.php` เพื่อสร้างตารางจาก `database/schema.mysql.sql` และผู้ดูแลเริ่มต้น
4. ตั้ง DocumentRoot ของเว็บเซิร์ฟเวอร์ให้เป็นโฟลเดอร์ `public/` เท่านั้น และเปิด URL rewrite
5. บัญชีเริ่มต้นใช้ค่า ADMIN_EMAIL/ADMIN_PASSWORD ที่ตั้งไว้ ไม่เขียน credentials ลงไฟล์ใน production
6. นำเข้าเนื้อหาจริงผ่าน Admin ข้อมูล SQLite ไม่ได้ถูกย้ายเข้า MySQL โดยอัตโนมัติ

ทดสอบการนำเข้าข้อมูลชุดติดตั้งกับ MySQL 8.4.11 ในเครื่องแล้ว รวมถึงการเปิดหน้าเว็บและเข้าสู่ระบบ Admin ส่วนโฮสติ้ง InfinityFree ยังต้องติดตั้งและตรวจจริง การทดสอบ regression ปกติใช้ SQLite แยกจากข้อมูลเว็บ

สำหรับ Apache มี `public/.htaccess` ให้แล้ว สำหรับ Nginx ใช้ `try_files $uri /index.php?$query_string;` และส่งไฟล์ PHP ไปยัง PHP-FPM ตามการตั้งค่าเซิร์ฟเวอร์ของหน่วยงาน อย่าใช้ PHP development server สำหรับเว็บไซต์สาธารณะจริง

## ฟังก์ชันที่มี

- หน้าแรก ข่าวและรายละเอียด กิจกรรมและรายละเอียด คลังภาพ/วิดีโอ/เอกสาร บุคลากร ติดต่อ และค้นหา
- กรองหมวดข่าว ช่วงวันที่ เดือนกิจกรรม คำค้น และแบ่งหน้า
- อัลบั้มเปิดภาพใหญ่ด้วยคีย์บอร์ดได้ ปุ่มคัดลอกลิงก์ และเอกสารดาวน์โหลด
- Admin: ข่าว กิจกรรม อัลบั้ม วิดีโอ เอกสาร หน้าเว็บไซต์ แบนเนอร์ หมวดข่าว บุคลากร ผู้ใช้ ตั้งค่า และบันทึกการใช้งาน
- ตัวแก้ไขข่าวรองรับหัวข้อ ตัวหนา ตัวเอียง รายการ และลิงก์ผ่านรูปแบบ Markdown แบบจำกัด โดยไม่อนุญาต HTML โดยตรง
- ร่าง เผยแพร่ ตั้งเวลา เก็บเข้าคลัง ถังขยะ และนำรายการในถังขยะกลับมาแก้สถานะ
- ตรวจเวอร์ชันก่อนบันทึกเพื่อป้องกันการเขียนทับการแก้ไขของผู้อื่น และเก็บ snapshot ทุกการบันทึกเนื้อหา
- เปลี่ยน URL แล้วมี redirect จาก URL เดิม
- ผู้ดูแลระบบจัดการบัญชีทั้งหมด บรรณาธิการจัดการเนื้อหาและบุคลากร ผู้เขียนแก้ได้เฉพาะข่าวร่างของตนเอง
- เปลี่ยนภาพเด่นหน้าแรกได้จากตั้งค่า โดยเลือกภาพจากคลังสื่อ
- วิดีโอใช้ลิงก์เปิดเว็บไซต์ต้นทาง ไม่มีการอัปโหลดหรือแปลงไฟล์วิดีโอในระบบนี้
- API อ่านข้อมูล: `GET /api/news`, `/api/events`, `/api/personnel`; การแก้ข้อมูลใช้ฟอร์ม Admin ที่ตรวจสิทธิ์และ CSRF

## การเผยแพร่ตามเวลา

ข้อมูลตั้งเวลาจะมองเห็นบนเว็บไซต์เมื่อถึงเวลาที่ตั้งไว้ โดยตรวจจากเวลาไทยทุกครั้งที่อ่านข้อมูล ไม่ต้องพึ่ง worker เพื่อให้หน้าเว็บแสดงรายการ

เพื่อเปลี่ยนสถานะใน Admin จากตั้งเวลาเป็นเผยแพร่ และบันทึกเหตุการณ์ ให้รัน `php bin/publish.php` ทุกนาทีผ่าน cron ของเซิร์ฟเวอร์ คำสั่งนี้ล้างประวัติลองเข้าสู่ระบบที่เก่ากว่า 24 ชั่วโมงด้วย

## ไฟล์และการดูแล

- ไฟล์อัปโหลดอยู่ใน `storage/uploads/` นอก DocumentRoot เปิดผ่าน `/files/{id}` ซึ่งตรวจว่ามีรายการสาธารณะอ้างอิงไฟล์ หรือผู้ดูมีบัญชีเจ้าหน้าที่
- รองรับ JPG, PNG, WebP, PDF สูงสุด 10 MB; ตรวจ MIME จริง ภาพสูงสุด 24 ล้านพิกเซลและแปลงเป็น WebP ด้านยาวไม่เกิน 3,840 px สำหรับภาพแสดงบนเว็บ (ต้นฉบับที่ดาวน์โหลดไม่ถูกย่อ)
- ลบไฟล์ที่ถูกใช้ในข่าว บุคลากร หรือภาพหน้าแรกไม่ได้
- คลังสื่อเลือกหลายไฟล์หรือเลือกทั้งโฟลเดอร์ได้ รูป JPG/PNG/WebP ในโฟลเดอร์ย่อยจะถูกรวมเข้าในคลังสื่อ ไฟล์อื่นจะถูกข้าม โดยไม่ได้สร้างโครงสร้างโฟลเดอร์บนเซิร์ฟเวอร์
- อัปโหลดทีละไฟล์ แสดงจำนวนสำเร็จ/ข้าม/ไม่สำเร็จพร้อมความคืบหน้า หยุดหลังไฟล์ปัจจุบันและลองอัปโหลดไฟล์ที่เหลือต่อได้ โดยไม่อัปโหลดรายการสำเร็จซ้ำ
- เบราว์เซอร์ที่ไม่รองรับเลือกโฟลเดอร์ใช้หลายไฟล์แทน; หากปิด JavaScript ยังอัปโหลดทีละไฟล์ได้
- เซิร์ฟเวอร์ต้องตั้ง `upload_max_filesize` อย่างน้อย `10M` และ `post_max_size` มากกว่า เช่น `12M` เพื่อรองรับขนาดสูงสุดตาม UI
- การเลือกโฟลเดอร์ใช้ [webkitdirectory](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/webkitdirectory) และส่งแต่ชื่อไฟล์ไปยังเซิร์ฟเวอร์ ไม่ใช้ relative path เป็นที่อยู่จัดเก็บ ตามข้อควรระวังใน [PHP Multiple Uploads](https://www.php.net/manual/en/features.file-upload.multiple.php)
- แหล่งอ้างอิงไฟล์ที่ยังเผยแพร่อยู่รายการอื่นทำให้ไฟล์ยังเป็นสาธารณะ แม้ถอนการเผยแพร่จากรายการหนึ่งแล้ว
- สำรองทั้ง MySQL dump (หรือ SQLite ที่สำรองอย่างถูกต้อง), `storage/uploads/`, โค้ด และ `.env` ที่เก็บอย่างปลอดภัย แล้วทดลองกู้คืนก่อนเปิดเว็บไซต์จริง
- ลืมรหัสผ่าน: ผู้ดูแลเปลี่ยนใน Admin หรือใช้ `php bin/reset-password.php email@example.com` ผ่านเครื่องเซิร์ฟเวอร์ ไม่มีระบบส่งอีเมลรีเซ็ตรหัสผ่านในรุ่นนี้
- Session หมดอายุหลังไม่มีการใช้งาน 2 ชั่วโมง ต้องเข้าสู่ระบบใหม่; ข้อมูลฟอร์มที่ยังไม่บันทึกไม่ถือว่าเก็บบนเซิร์ฟเวอร์แล้ว
- บัญชีเริ่มต้นและ `.env` ไม่ถูกเสิร์ฟผ่านเว็บไซต์ และถูกละเว้นจาก Git

## ข้อมูลตัวอย่างและทรัพยากร

- โลโก้ใช้ไฟล์ `Logo_of_Suan_Dusit_University.svg.webp` ที่มีในโครงการ
- ภาพ `public/assets/campus.webp` สร้างด้วย ImageGen เป็นภาพมหาวิทยาลัยจำลอง ไม่ใช่ภาพสถานที่จริงของสวนดุสิต ใช้เพื่อทดสอบหน้าตาตามแบบ
- Prompt ภาพ: generic Thai university campus, cream academic buildings, lush trees, students walking along a pathway, editorial photography, no logo or text, not a documentary representation of a specific university
- บุคลากรและข้อมูลติดต่อไม่สร้างข้อมูลจริงสมมติ ต้องเพิ่มข้อมูลที่มหาวิทยาลัยยืนยันผ่าน Admin
- เมื่อแทนข้อมูลและภาพตัวอย่างครบแล้ว ปิดป้ายเว็บไซต์ตัวอย่างที่เมนูตั้งค่า
- ฟอนต์ Noto Sans Thai เก็บในโครงการ ใบอนุญาตอยู่ใน `public/assets/FONT-LICENSE.txt`

## ทดสอบ

```sh
php tests/integration.php
npm install
npx playwright install chromium
npm run test:browser
```

หากมี Chrome อยู่แล้ว ตั้ง `CHROME_PATH` เป็น executable ของ Chrome แทนการดาวน์โหลด Chromium

การทดสอบเบราว์เซอร์เปิดเซิร์ฟเวอร์ที่ 8081 และฐานข้อมูลแยกใน `tests/.runtime/` โดยไม่แก้ข้อมูลเว็บไซต์ที่ 8080 ภาพหน้าจออยู่ใน `artifacts/` ตรวจหน้าเว็บไซต์/Admin การบันทึกและเผยแพร่ สิทธิ์ CSRF อัปโหลดไฟล์ การเปิดภาพใหญ่ และหน้าจอ 320/360/768/1440 px

ใช้ prepared statements, password_hash/password_verify และ Session Cookie แบบ HttpOnly/SameSite ตาม [เอกสาร PHP PDO](https://www.php.net/manual/en/pdo.prepared-statements.php), [password_hash](https://www.php.net/manual/en/function.password-hash.php) และ [session_set_cookie_params](https://www.php.net/manual/en/function.session-set-cookie-params.php)

เอกสารออกแบบเดิมและภาพ Mockup อยู่ใน `design/` เป็นประวัติขั้นออกแบบ ส่วน README นี้อธิบายสถานะระบบที่พัฒนาแล้ว

ข้อมูลหน้าบุคลากรนำเข้าจากเอกสารโครงสร้างและภาระงาน ลงวันที่ 6 ตุลาคม 2569 โดยใช้ `php bin/import-pr-profile.php` กับฐานข้อมูลที่ตั้งค่าไว้ สคริปต์เพิ่มเฉพาะชื่อที่ยังไม่มี และคงข้อมูลเดิมกับรูปบุคลากรไว้ สามารถแก้ไขชื่อ ตำแหน่ง รูป และการเผยแพร่ผ่าน `/admin/personnel` ได้ ข้อมูลโครงสร้าง พันธกิจ และภาระงานจัดเก็บใน setting `personnel_profile` จาก `database/imports/pr-profile-2026.json` เอกสารไม่ได้ระบุตำแหน่งของทุกคนเป็นรายบุคคล จึงใช้คำว่า “บุคลากรกองประชาสัมพันธ์” สำหรับรายชื่อที่ไม่มีตำแหน่งชัดเจน และไม่อนุมานกลุ่มงานรายบุคคลจากกล่องข้อความในผัง

คลังสื่อรองรับโฟลเดอร์ตามงาน: สร้างโฟลเดอร์ที่ Admin → คลังสื่อ เลือกโฟลเดอร์ปลายทางก่อนอัปโหลด และย้ายไฟล์เดิมผ่านตัวเลือกโฟลเดอร์บนแต่ละรูป ในหน้าแก้ไขอัลบั้มเลือกกรองโฟลเดอร์ของงานได้ ปุ่มเลือกทั้งหมดทำงานเฉพาะไฟล์ที่แสดงและคงรายการที่เลือกไว้ในโฟลเดอร์อื่น รูปเดิมอยู่ใน “ยังไม่จัดโฟลเดอร์” จนกว่าจะจัดหมวดหมู่ โฟลเดอร์เป็นการจัดหมวดหมู่ในฐานข้อมูล ส่วนไฟล์ยังจัดเก็บด้วยชื่อสุ่มในพื้นที่ส่วนตัวเพื่อคงลิงก์เดิม หากอัปเกรดฐานข้อมูลเดิมให้รัน `php bin/setup.php` เพื่อเพิ่มตาราง `media_folders` และ `media_folder_items` โดยไม่ลบข้อมูลเดิม

รหัสผ่านใหม่ต้องยาว 6–12 ตัวอักษร ตรวจเงื่อนไขที่เซิร์ฟเวอร์และปฏิเสธตัวอย่างรหัสทั่วไปที่เดาง่าย แนะนำใช้ 12 ตัวอักษรที่สุ่มและไม่ใช้ซ้ำ รหัสเดิมยังเข้าสู่ระบบได้ เก็บรหัสผ่านเป็น hash ด้วย PHP password_hash/password_verify และจำกัดการเข้าสู่ระบบผิด 5 ครั้งใน 15 นาทีต่อบัญชี/IP ความยาว 6 ตัวมีความเสี่ยงสูงกว่ารหัสยาว; นโยบายนี้เป็นข้อกำหนดเฉพาะโครงการ ไม่ใช่การอ้างว่าตรงตามคำแนะนำทั้งหมดของ OWASP: https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html

แนบไฟล์ได้สูงสุด 1,000 รายการต่อเนื้อหา ต้องตั้ง PHP `max_input_vars=2000` เพื่อรองรับช่องเลือกไฟล์และข้อมูลอื่นในฟอร์ม เมื่อเปิด JavaScript ระบบจะส่งรายการภาพเป็น JSON หนึ่งฟิลด์เพื่อรองรับโฮสต์ที่ตั้ง max_input_vars=1000; ค่า 2000 ยังแนะนำสำหรับการใช้งานโดยปิด JavaScript

ข่าวประชาสัมพันธ์รองรับ “ลิงก์ไปเว็บไซต์อื่น”: เลือกรูปแบบข่าวในหน้า Admin แล้วกรอกชื่อข่าวกับ URL http/https ก็เผยแพร่ได้ โดยไม่ต้องใส่เนื้อหา หมวดหมู่ หรือรูปปก ผู้ชมกดการ์ดข่าวเพื่อเปิดเว็บปลายทางโดยตรง ลิงก์รายละเอียดเดิมของข่าวจะส่งต่อแบบ 302 เฉพาะข่าวที่เผยแพร่แล้ว ข่าวรูปแบบปกติยังใช้เงื่อนไขการเผยแพร่เดิม

ภาพที่อัปโหลดใหม่เก็บ 2 ไฟล์: ต้นฉบับที่ไม่แปลง/ไม่ลดขนาด และ WebP สำหรับแสดงหน้าเว็บ ปุ่มดาวน์โหลดส่งไฟล์ต้นฉบับพร้อมชนิดไฟล์เดิม โดยใช้สิทธิ์การเข้าถึงเดียวกับรูปบนเว็บ เก็บ metadata ในตาราง `media_originals` อัปเกรดฐานข้อมูลด้วย `php bin/setup.php` ก่อนใช้โค้ดเวอร์ชันนี้ การลบไฟล์จะลบทั้งต้นฉบับและภาพตัวอย่าง และแพ็กเกจติดตั้งจะรวมต้นฉบับด้วย รูปที่อัปโหลดก่อนเวอร์ชันนี้มีเพียง WebP ที่แปลงแล้ว จะดาวน์โหลดไฟล์ที่มีอยู่ และต้องอัปโหลดต้นฉบับใหม่หากต้องการคุณภาพเดิม
