## เส้นทางสำหรับ Prototype รอบถัดไป

1. หน้าแรก → รายการข่าว → กรองหมวด → รายละเอียด → คัดลอกลิงก์
2. หน้าแรก → กิจกรรม → รายละเอียดกิจกรรม → กลับรายการ
3. คลังสื่อ → อัลบั้ม → ดูภาพใหญ่ → ปิดกลับอัลบั้ม
4. คลังสื่อ → เอกสาร → ดูข้อมูลไฟล์ → ดาวน์โหลดตัวอย่าง
5. Admin → ข่าว → สร้าง → กรอกข้อมูล → บันทึกร่าง → ดูตัวอย่าง
6. Admin บรรณาธิการ → ตรวจข่าวร่าง → เผยแพร่หรือตั้งเวลา

ภาพ Mockup เป็นภาพนิ่ง ไม่มีปุ่มที่ทำงานจริงและไม่ทดแทนการทดสอบ Prototype

ภาพรอบกิจกรรมและคลังสื่อ: `mockups/activities-media-mobile-v1.png` สร้างด้วย ImageGen โดยใช้ภาพหน้าข่าวและ Admin เป็นแนวทางอ้างอิง

สรุปโจทย์ภาพ: หน้ากิจกรรมและคลังสื่อ Desktop พร้อมกิจกรรม คลังสื่อ และอ่านข่าว Mobile ใช้สีฟ้า–ขาว–ดำ ตัวอักษรไทย และ SDU เป็นโลโก้ชั่วคราว ภาพและข้อมูลเป็นตัวอย่าง

ภาพรอบรายละเอียดและค้นหา: `mockups/event-album-contact-search-v1.png` สร้างด้วย ImageGen อ้างอิงภาพกิจกรรมและคลังสื่อรอบก่อน

สรุปโจทย์ภาพ: รายละเอียดกิจกรรม อัลบั้มภาพ ติดต่อ และผลการค้นหาในบอร์ด 4 หน้าจอ ใช้ดีไซน์เดิม ข้อมูลติดต่อและวันเวลารอยืนยัน ไม่สร้างข้อมูลจริงสมมติ

แผนเชื่อมหน้าจอและเกณฑ์ตรวจ Prototype อยู่ใน `prototype-plan.md` ยังไม่มี Prototype ที่กดได้จริง

การแก้ตามผู้ใช้: เปลี่ยนเมนู “เกี่ยวกับเรา” เป็น “บุคลากร” สำหรับกองประชาสัมพันธ์ทุกหน้า ภาพเก่าที่ยังมีเมนูเดิมเป็นแบบก่อนการแก้นี้

ภาพบุคลากร: `mockups/personnel-desktop-mobile-v1.png` สร้างด้วย ImageGen โดยอ้างอิงดีไซน์เดิม โจทย์ภาพเป็นหน้าบุคลากร Desktop/Mobile ใช้เมนูบุคลากรและการ์ดรูป ชื่อ ตำแหน่ง โดยไม่สมมติรายชื่อหรือโครงสร้างหน่วยงาน รูปบุคคลเป็นภาพสร้างขึ้น ไม่ใช่บุคลากรจริง

## ข้อสังเกตจากการตรวจภาพรอบนี้

- ภาพแสดงโครงสร้างหลักและสีสอดคล้องกับแบบก่อนหน้า
- มือถือคลังสื่อในภาพใช้ภาพย่อกับข้อความแนวนอน เมื่อจัดทำ Prototype ให้ใช้การ์ดภาพด้านบนตามข้อกำหนด หรือทดสอบก่อนเลือกแบบย่อ
- มือถือค้นหากิจกรรมในภาพยังวางคำค้นกับเดือนข้างกัน ให้เรียงแนวตั้งใน Prototype เมื่อความกว้างไม่พอ
- ภาพรายละเอียดข่าวมีตัวอย่าง Metadata ซ้ำ ขณะจัดทำ Prototype ให้แทนด้วยวันเผยแพร่และวันปรับปรุงเฉพาะเมื่อมี
- ภาพนิ่งไม่ยืนยันขนาดพื้นที่กด ความต่างสี การตัดบรรทัด หรือการใช้คีย์บอร์ด ต้องตรวจจาก Prototype จริง
- ในกรณีภาพกับข้อกำหนดขัดกัน ให้ใช้ `ui-ux-spec.md` เป็นหลักและปรับแบบก่อนพัฒนา

## จุดที่ต้องตรวจในการทดสอบ

- ผู้อ่านหาข่าวและกิจกรรมได้โดยเข้าใจชื่อเมนู
- ผู้ใช้แยกกิจกรรมที่กำลังจะมาถึง ย้อนหลัง และยกเลิกได้
- ผู้ใช้แยกภาพ วิดีโอ และเอกสารในคลังสื่อได้
- การใช้บนมือถือไม่ต้องขยายหน้าจอเพื่ออ่านข้อความหลัก
- ผู้เขียนแยกบันทึกร่างจากเผยแพร่ และเห็นข้อมูลที่ต้องกรอกได้
- คงค่าค้นหาและตัวกรองเมื่อย้อนกลับจากรายละเอียด
- ข้อความผิดพลาดบอกวิธีดำเนินการต่อโดยไม่ทำข้อมูลหาย

เกณฑ์นี้ยังไม่ถูกทดสอบกับระบบจริง ต้องตรวจซ้ำในขั้น Prototype และพัฒนา
