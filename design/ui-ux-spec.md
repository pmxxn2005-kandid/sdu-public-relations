# UI/UX Specification — กองประชาสัมพันธ์ มหาวิทยาลัยสวนดุสิต

วันที่: 9 ตุลาคม 2569

## สถานะและขอบเขต

เอกสารข้อกำหนดจากขั้นออกแบบก่อนพัฒนา ผู้ใช้สั่งเริ่มเขียนโค้ดแล้วเมื่อ 9 ตุลาคม 2569 สถานะระบบและวิธีรันปัจจุบันอยู่ใน `../README.md` ภาพ Mockup ยังคงเป็นแนวทางออกแบบ ไม่ใช่ภาพระบบที่ทำงานจริง

ระยะแรก: เว็บไซต์ประชาสัมพันธ์ ระบบ Admin จัดการเนื้อหา และ MySQL ไม่รวมสมาชิกสาธารณะ ความคิดเห็น และระบบอนุมัติหลายระดับ

โลโก้ ภาพบุคคล/อาคาร และข่าวใน Mockup เป็นตัวอย่าง ต้องแทนด้วยสื่อที่มหาวิทยาลัยอนุมัติก่อนเผยแพร่ ภาพสร้างขึ้นไม่ใช่หลักฐานภาพสถานที่จริง

## แนวทางภาพรวม

- สีตั้งต้น: ฟ้า #149FE3, ฟ้าอ่อน #EDF8FF, ขาว #FFFFFF, ข้อความ #171B21, ข้อความรอง #586473, เส้นแบ่ง #DDE5EB ต้องตรวจความต่างสีเมื่อจัดทำหน้าจอจริง
- ค่าสีแบรนด์รอเทียบกับโลโก้หรือคู่มืออัตลักษณ์จริง
- ตัวอักษรไทยอ่านง่าย ขนาดเนื้อหาเริ่มต้น 16–18 px ระยะบรรทัด 1.6–1.8
- ความกว้างเนื้อหาหลักประมาณ 1,200 px; เนื้อหาบทความประมาณ 760 px
- ระบบระยะห่าง 8, 16, 24, 32, 48 และ 64 px; มุมการ์ด 12 px
- ภาพปกข่าวสัดส่วน 16:9 มีจุดโฟกัสและข้อความอธิบายภาพ
- หน้าแรกเน้นข่าวหรือภาพเด่นหนึ่งรายการ ไม่เปลี่ยนสไลด์อัตโนมัติ
- มือถือเริ่มออกแบบที่ 360 px และตรวจเพิ่มที่ 320 px; แท็บเล็ต 768 px; Desktop 1,440 px

## หน้ารวมข่าว

Header → Breadcrumb → ชื่อหน้าและคำอธิบาย → ค้นหา/ตัวกรอง → จำนวนผลลัพธ์ → การ์ดข่าว → Pagination → Footer

- Desktop การ์ด 3 คอลัมน์; Tablet 2; Mobile 1
- ตัวกรอง: คำค้น หมวดหมู่ และช่วงวันที่ เรียงใหม่ล่าสุดเป็นค่าเริ่มต้น
- ค้นหาเมื่อกดค้นหาหรือ Enter; ล้างตัวกรองได้
- คงคำค้น ตัวกรอง และเลขหน้าใน URL เพื่อย้อนกลับและแชร์ได้
- การ์ด: ภาพปก หมวดหมู่ ชื่อ คำโปรย วันที่เผยแพร่
- ไม่แสดงข่าวร่าง ข่าวที่ยังไม่ถึงเวลา หรือข่าวในถังขยะ
- สถานะ: กำลังโหลด / ไม่พบผลลัพธ์ / โหลดไม่สำเร็จและลองใหม่
- ตัวอย่างข่าวต้องติดป้ายว่าเป็นตัวอย่าง หลีกเลี่ยงวันหรือเหตุการณ์ที่ดูเป็นประกาศจริง

## หน้ารายละเอียดข่าว

Header → Breadcrumb → หมวดหมู่ → ชื่อข่าว → คำโปรย → วันที่เผยแพร่และปรับปรุง → ภาพปก → เนื้อหา → ภาพประกอบ → ไฟล์แนบ → แชร์ → ข่าวที่เกี่ยวข้อง → Footer

- แสดงเครดิตภาพและผู้เขียนเฉพาะเมื่อหน่วยงานต้องการเปิดเผย
- วันปรับปรุงแสดงเมื่อมีการแก้ไขหลังเผยแพร่
- ไฟล์แนบแสดงชื่อ ประเภท ขนาด และปุ่มดาวน์โหลด
- ปุ่มแชร์รองรับคัดลอกลิงก์ พร้อมข้อความยืนยันที่อ่านได้ด้วยเทคโนโลยีช่วยเหลือ
- ข่าวที่เกี่ยวข้องไม่รวมข่าวปัจจุบันและข่าวที่ไม่เผยแพร่
- มีทางกลับรายการข่าว พร้อมรักษาตัวกรองเดิมเมื่อเปิดจากรายการ
- หากไม่พบข่าวแสดงหน้าไม่พบเนื้อหา หากเปลี่ยน URL ต้องมีการเปลี่ยนเส้นทางจาก URL เดิม

## หน้ากิจกรรมและรายละเอียดกิจกรรม

Header → Breadcrumb → ชื่อหน้า → ตัวกรอง → รายการกิจกรรม → Pagination → Footer

- ค่าเริ่มต้นแสดงกิจกรรมที่กำลังจะมาถึง เรียงวันเริ่มจากใกล้ที่สุดก่อน
- แท็บ: กำลังจะมาถึง / ย้อนหลัง; ตัวกรองคำค้นและเดือนพร้อมปี
- ใช้รายการกิจกรรมเป็นมุมมองหลัก เพื่อให้เห็นชื่อและรายละเอียดได้ทั้งบน Desktop และมือถือ ไม่เพิ่มปฏิทินเต็มเดือนในระยะแรก
- การ์ด: ภาพ ชื่อ วันเริ่มและสิ้นสุด เวลา สถานที่ และป้ายสถานะ
- กิจกรรมข้ามวันแสดงช่วงวันเต็ม กิจกรรมออนไลน์แสดงเป็นออนไลน์และระบุช่องทาง
- หน้ารายละเอียด: ชื่อ / สถานะ / ภาพ / วันเวลา / สถานที่ / คำอธิบาย / ผู้ประสานงานที่ได้รับอนุญาตให้เปิดเผย / ลิงก์ภายนอกถ้ามี
- แยกสถานะเผยแพร่ของเนื้อหาออกจากสถานะกิจกรรม: กำลังจะมาถึง / กำลังจัด / สิ้นสุดแล้ว / ยกเลิก
- กิจกรรมที่ยกเลิกยังเปิดอ่านได้พร้อมป้ายแจ้งชัดเจน และไม่แสดงปุ่มลงทะเบียน
- ลิงก์ลงทะเบียนภายนอกแสดงเมื่อมีข้อมูลจริงและอยู่ในช่วงรับสมัคร ไม่สร้างระบบลงทะเบียนภายใน
- วันเวลาใช้งานจริงแสดงปี พ.ศ. และเวลาไทย; ตัวอย่าง Mockup ใช้คำว่าวันเวลารอประกาศ
- หากไม่มีกิจกรรมให้แสดงข้อความและทางไปกิจกรรมย้อนหลัง

## คลังสื่อและดาวน์โหลด

Header → Breadcrumb → ชื่อหน้า → แท็บประเภทสื่อ → ค้นหา/ตัวกรอง → รายการ → Pagination → Footer

- แท็บ: อัลบั้มภาพ / วิดีโอ / เอกสาร
- อัลบั้ม: ภาพปก ชื่อ จำนวนภาพ วันที่เผยแพร่; Desktop 3 คอลัมน์ Tablet 2 Mobile 1
- รายละเอียดอัลบั้ม: ชื่อ คำอธิบาย เครดิต และภาพที่เรียงตามลำดับเจ้าหน้าที่กำหนด
- เปิดภาพในหน้าต่างดูภาพขนาดใหญ่ มีปุ่มก่อนหน้า ถัดไป ปิด และคำบรรยาย; รองรับ Escape และคืนโฟกัสเมื่อปิด
- อนุญาตดาวน์โหลดภาพเฉพาะรายการที่หน่วยงานกำหนดให้ดาวน์โหลดได้ ไม่ถือว่าทุกไฟล์ใน Admin เป็นสื่อสาธารณะ
- วิดีโอ: ภาพปก ชื่อ คำอธิบาย และช่องทางที่เผยแพร่ ไม่เล่นอัตโนมัติ; มีลิงก์ต้นทางเมื่อฝังวิดีโอไม่สำเร็จ
- เอกสาร: ชื่อ คำอธิบาย ประเภท ขนาด วันที่ปรับปรุง และปุ่มดาวน์โหลด
- ตรวจชื่อไฟล์ยาวบนมือถือให้ตัดบรรทัดได้ ไม่ทำให้หน้าเกิดการเลื่อนแนวนอน
- แสดงคำแนะนำการใช้หรือเครดิตสื่อเมื่อมีข้อกำหนดจากหน่วยงาน
- การถอนการเผยแพร่ต้องตรวจการเข้าถึงไฟล์ต้นฉบับด้วย ไม่ใช่เพียงซ่อนการ์ด
- ภาพไม่มี/ลิงก์วิดีโอเสีย/เอกสารไม่พบ แสดงข้อความเฉพาะและไม่สร้างปุ่มที่ใช้งานไม่ได้

## หน้าค้นหาและติดต่อ

- ค้นหา: ช่องคำค้น / จำนวนผลลัพธ์ / กรองประเภทข่าว กิจกรรม เอกสาร / รายการผล / Pagination
- ผลการค้นหาแสดงชื่อ ประเภท วันที่ และคำโปรยสั้น; ค้นหาเฉพาะข้อมูลเผยแพร่ ไม่ค้นข้อความใน PDF ในระยะแรก
- หน้าค้นหาก่อนกรอกคำแสดงข้อความให้เริ่มค้นหา โดยไม่แสดงว่าเกิดข้อผิดพลาด
- ติดต่อ: ที่อยู่ โทรศัพท์ อีเมล เวลาทำการ และลิงก์แผนที่ที่หน่วยงานยืนยัน
- มือถือกดโทรศัพท์หรืออีเมลได้เมื่อมีข้อมูลจริง; ลิงก์แผนที่ใช้คำชัดเจน
- ไม่เพิ่มฟอร์มรับเรื่องติดต่อในระยะแรก เพื่อคงขอบเขตเว็บไซต์ประชาสัมพันธ์และ Admin
- หน้านโยบายใช้ข้อความที่หน่วยงานรับรอง ไม่สร้างข้อความทางกฎหมายแล้วอ้างว่าได้รับรอง

## หน้าบุคลากรกองประชาสัมพันธ์

เมนูหลักใช้ชื่อ “บุคลากร” แทน “เกี่ยวกับเรา” ใน Header, เมนูมือถือ, Footer และ Sitemap ทุกหน้า

Header → Breadcrumb → ชื่อหน้า “บุคลากรกองประชาสัมพันธ์” → ชื่อมหาวิทยาลัย → บุคลากรตามลำดับที่หน่วยงานกำหนด → ช่องทางติดต่อกอง → Footer

- แสดงรูป ชื่อ–นามสกุล ตำแหน่ง และกลุ่มงานเมื่อมีข้อมูลที่รับรองแล้ว
- หากหน่วยงานกำหนดผู้บริหารหรือหัวหน้ากอง ให้แสดงส่วนแรกก่อนกลุ่มบุคลากร ไม่สมมติโครงสร้างหรือตำแหน่งจริง
- Desktop แสดงการ์ด 3 คอลัมน์ Tablet 2 Mobile 1; รูปบุคคลสัดส่วน 4:5 และเลือกจุดโฟกัสได้
- เรียงตามลำดับที่กำหนดโดย Admin ไม่เรียงอักษรเป็นค่าเริ่มต้น
- ไม่มีรูปใช้ภาพแทนกลาง ไม่มีข้อมูลกลุ่มงานให้ซ่อนบรรทัดนั้น
- แสดงเฉพาะข้อมูลที่อนุมัติให้เผยแพร่ ไม่แสดงโทรศัพท์หรืออีเมลส่วนบุคคลเป็นค่าเริ่มต้น
- ใช้ช่องทางติดต่อกองเป็นหลัก; ช่องทางรายบุคคลเป็นตัวเลือกเฉพาะข้อมูลสำหรับงานที่ได้รับอนุญาต
- ไม่เปิดหน้าประวัติรายบุคคลในระยะแรก การ์ดที่ไม่มีหน้ารายละเอียดไม่ออกแบบเหมือนปุ่ม
- ไม่เพิ่มค้นหาหรือตัวกรองรายชื่อจนกว่าจำนวนบุคลากรจริงจะทำให้จำเป็น
- ตัวอย่างรูปและข้อความต้องระบุว่าเป็นตัวอย่าง ไม่ใส่ชื่อหรือตำแหน่งจริงที่ไม่ได้รับข้อมูล
- หากยังไม่มีรายการเผยแพร่ แสดง “กำลังปรับปรุงข้อมูลบุคลากร” และลิงก์ติดต่อกอง

### Admin: จัดการบุคลากร

- เพิ่มเมนูบุคลากร พร้อมรายการชื่อ ตำแหน่ง กลุ่มงาน ลำดับ สถานะ และคำสั่งแก้ไข
- ฟอร์ม: ชื่อ–นามสกุล / ตำแหน่ง / กลุ่มงาน (ไม่บังคับ) / รูป / ข้อความอธิบายภาพ / ลำดับ / สถานะเผยแพร่
- ชื่อและตำแหน่งบังคับก่อนเผยแพร่ รูปเป็นตัวเลือกและมีภาพแทนเมื่อไม่มี
- บันทึกร่าง ดูตัวอย่าง เปิดหรือปิดการเผยแพร่ และจัดลำดับได้
- ผู้ดูแลระบบและบรรณาธิการจัดการได้ ผู้เขียนข่าวไม่มีสิทธิ์แก้ข้อมูลบุคลากรโดยค่าเริ่มต้น
- ใช้ข้อมูลบุคลากรแยกจากบัญชี Admin บุคลากรหนึ่งคนไม่จำเป็นต้องมีบัญชีเข้าสู่ระบบ
- โครงสร้างข้อมูลในขั้นออกแบบเพิ่ม `personnel` เก็บชื่อ ตำแหน่ง กลุ่มงาน รูป ลำดับ และสถานะ; ยังไม่สร้างตารางจริง
- บันทึกประวัติการเปลี่ยนแปลงและป้องกันการลบรูปที่ยังใช้งานอยู่

ภาพร่างก่อนการแก้เมนูนี้ยังมีคำว่า “เกี่ยวกับเรา” ให้ถือว่าชื่อเมนูในภาพเก่าถูกแทนด้วย “บุคลากร” และปรับใน Prototype ทุกหน้า

## รายละเอียดหน้าจอชุดสุดท้ายก่อน Prototype

### รายละเอียดกิจกรรม

Breadcrumb → สถานะกิจกรรม → ชื่อและคำโปรย → ภาพปก → ข้อมูลวันเวลาและสถานที่ → รายละเอียด → ผู้ประสานงาน → กลับรายการกิจกรรม

- Desktop แยกบทความกับกล่องข้อมูลกิจกรรม; Mobile เรียงชื่อ ภาพ และกล่องข้อมูลก่อนบทความ
- กล่องข้อมูลมีวันเริ่ม/สิ้นสุด เวลา เขตเวลา และสถานที่ที่ยืนยันแล้ว
- หากวันเวลายังไม่ยืนยัน ใช้ข้อความรอประกาศ ไม่แสดงสถานะกำลังจะมาถึงที่คำนวณจากวันที่สมมติ
- ปุ่มลงทะเบียนเป็นตัวเลือก แสดงเฉพาะมี URL จริงและกิจกรรมเปิดรับสมัคร
- กิจกรรมยกเลิกแสดงข้อความยกเลิกใกล้ชื่อเรื่องและเหตุผลที่ได้รับอนุญาตให้เผยแพร่
- ปุ่มกลับรายการรักษาแท็บ คำค้น เดือน ปี และเลขหน้าเดิม

### รายละเอียดอัลบั้ม

Breadcrumb → ชื่ออัลบั้ม → คำอธิบาย/วันที่/เครดิต → ตารางภาพ → กลับคลังสื่อ

- Desktop 3 คอลัมน์ Tablet 2 Mobile 1–2 ตามความชัดเจนของภาพ; ไม่ครอปจนสาระภาพหาย
- ภาพย่อแต่ละภาพเป็นปุ่มเปิดดูภาพใหญ่พร้อมชื่อที่เทคโนโลยีช่วยเหลืออ่านได้
- ดูภาพใหญ่: ภาพ / คำบรรยาย / ลำดับภาพ / ก่อนหน้า / ถัดไป / ปิด
- โฟกัสอยู่ในหน้าต่างขณะเปิด ใช้ลูกศรเปลี่ยนภาพและ Escape ปิด; คืนโฟกัสที่ภาพเดิม
- การดาวน์โหลดใช้สิทธิ์ของแต่ละภาพ หากไม่อนุญาตให้ซ่อนปุ่มดาวน์โหลด แต่ไม่อ้างว่าห้ามบันทึกภาพสาธารณะได้สมบูรณ์
- ไม่เพิ่ม ZIP ดาวน์โหลดอัลบั้มทั้งหมดในระยะแรก

### ติดต่อเรา

Breadcrumb → ชื่อหน้า → ข้อมูลติดต่อ → ช่องทางสังคมออนไลน์ → ลิงก์แผนที่ → Footer

- กล่องข้อมูลใช้ชื่อหน่วยงาน ที่อยู่ โทรศัพท์ อีเมล และเวลาทำการที่ยืนยันแล้ว
- Mockup ใช้ข้อความรอยืนยัน ไม่สร้างหมายเลข อีเมล หรือแผนที่ที่ดูเป็นข้อมูลจริง
- ระยะแรกใช้ลิงก์เปิดแผนที่แทนบังคับฝังแผนที่ ลดทรัพยากรภายนอกและใช้งานได้เมื่อฝังไม่สำเร็จ
- ข้อมูลที่ยังไม่ยืนยันไม่สร้างปุ่มโทร ส่งอีเมล หรือเปิดแผนที่ที่ทำงานจริง
- ไม่มีฟอร์มรับเรื่องติดต่อหรือร้องเรียนในขอบเขตนี้

### ผลการค้นหา

Breadcrumb → ชื่อหน้า → ช่องคำค้นและปุ่มค้นหา → ประเภทเนื้อหา → จำนวนผลลัพธ์ → รายการผล → Pagination

- รายการผลเป็นแถว แสดงประเภท ชื่อ คำโปรย วันที่ และภาพย่อเมื่อมี
- ประเภทเนื้อหา: ทั้งหมด / ข่าว / กิจกรรม / เอกสาร
- ค้นแบบส่งฟอร์มด้วยปุ่มหรือ Enter; คำค้นว่างแสดงคำแนะนำก่อนเริ่มค้นหา
- URL เก็บคำค้น ประเภท และเลขหน้า; ล้างประเภทเมื่อคำค้นใหม่ตามพฤติกรรมที่กำหนดใน Prototype
- จำกัดผลลัพธ์ให้เป็นข้อมูลที่เผยแพร่และผู้ใช้มีสิทธิ์เข้าถึง
- ไม่ดึงข้อมูล Admin และไม่ค้นข้อความใน PDF ในระยะแรก
- เมื่อไม่พบผล ให้คงคำค้นและเสนอแก้คำหรือล้างประเภท ไม่สร้างผลลัพธ์สมมติ

## รายละเอียดการแสดงผลบนมือถือ

- Header: โลโก้ ชื่อหน่วยงานแบบสองบรรทัด และปุ่มเมนู; ปุ่มค้นหาอยู่ในเมนูหากพื้นที่ไม่พอ
- เมนูเปิดแบบ Drawer มีปุ่มปิดและรายการเมนูครบ; เมื่อปิดคืนโฟกัสที่ปุ่มเปิดเมนู
- หัวข้อไทยยาวตัดบรรทัดได้ ไม่ย่อขนาดตัวอักษรเพื่อบังคับให้อยู่บรรทัดเดียว
- ช่องค้นหาและตัวกรองเรียงแนวตั้งพร้อมปุ่มค้นหาเต็มความกว้าง
- ปุ่มและลิงก์สำคัญมีพื้นที่กดประมาณ 44 × 44 px และไม่พึ่ง Hover
- หน้าอ่านข่าวแสดงรูปเต็มความกว้าง เนื้อหาคอลัมน์เดียว และไฟล์แนบที่ชื่อขึ้นบรรทัดใหม่ได้
- แท็บประเภทสื่อใช้ 3 ช่องที่อ่านได้; หมวดข่าวจำนวนมากใช้ตัวเลือกแทนแถบยาวล้นจอ
- Admin เรียงเนื้อหาก่อนการตั้งค่าเผยแพร่ ปุ่มบันทึกและเผยแพร่อยู่ท้ายฟอร์มและเข้าถึงได้โดยไม่บังช่องกรอก
- ทุกหน้าต้องใช้งานได้ที่ 320 px โดยไม่เลื่อนแนวนอน ยกเว้นองค์ประกอบข้อมูลที่จำเป็นและออกแบบแยกไว้

## Admin: โครงสร้างร่วม

- Desktop: Sidebar / แถบชื่อหน้ากับบัญชี / พื้นที่ทำงาน
- Mobile: เปิดเมนูเป็น Drawer และเรียงฟอร์มคอลัมน์เดียว
- เมนู: ภาพรวม ข่าว กิจกรรม คลังสื่อ บุคลากร หน้าเว็บไซต์ แบนเนอร์ หมวดหมู่และแท็ก ผู้ใช้ ตั้งค่า ประวัติการใช้งาน
- รายการข่าวแสดงชื่อ สถานะ หมวดหมู่ ผู้เขียน วันที่ และคำสั่งที่มีสิทธิ์
- Mobile เปลี่ยนตารางเป็นรายการการ์ดที่ยังเห็นชื่อและสถานะครบ
- ลบเข้าถังขยะก่อน; การลบถาวรต้องยืนยันรายการชัดเจน

## Admin: หน้าสร้างและแก้ไขข่าว

แถบหัว: ชื่อหน้า / บันทึกร่าง / ดูตัวอย่าง / เผยแพร่

คอลัมน์เนื้อหา: ชื่อข่าว / คำโปรย / เนื้อหา / รูปประกอบ / เอกสารแนบ

คอลัมน์การเผยแพร่: สถานะ / หมวดหมู่หลักหนึ่งหมวด / แท็กหลายรายการ / รูปปก / URL / เวลาเผยแพร่ / ชื่อและคำอธิบายสำหรับผลค้นหา

- ชื่อข่าว เนื้อหา หมวดหมู่ และรูปปกเป็นข้อมูลบังคับก่อนเผยแพร่ ร่างยอมให้กรอกไม่ครบได้
- URL สร้างจากชื่อได้และปรับเองได้ ต้องตรวจซ้ำ
- แสดงข้อความผิดพลาดข้างช่องที่เกี่ยวข้องและสรุปข้อผิดพลาดเมื่อเผยแพร่ไม่สำเร็จ
- ไม่อ้างว่าบันทึกอัตโนมัติหากยังไม่มีการบันทึกจริง แสดงเวลาบันทึกสำเร็จล่าสุด
- แจ้งเตือนก่อนออกจากหน้าเมื่อมีการเปลี่ยนแปลงที่ยังไม่บันทึก
- การดูตัวอย่างร่างต้องผ่านการตรวจสิทธิ์
- ตั้งเวลาใช้ Asia/Bangkok แสดงเวลาที่เลือกชัดเจนและตรวจวันที่ในอนาคต
- หากมีคนแก้ไขข่าวเดียวกัน ต้องแจ้งความขัดแย้งก่อนเขียนทับ
- ภาพและไฟล์แนบเลือกจากคลังเดิมได้ พร้อมความคืบหน้าและสถานะอัปโหลด
- คลังสื่อเลือกหลายไฟล์หรือทั้งโฟลเดอร์พร้อมโฟลเดอร์ย่อยได้ ส่งทีละไฟล์ แสดงสถานะรายไฟล์ และหยุด/อัปโหลดต่อได้
- โหมดโฟลเดอร์รับรูป JPG/PNG/WebP สูงสุด 10 MB ต่อไฟล์ รวมเข้าคลังสื่อโดยไม่สร้างโครงสร้างโฟลเดอร์บนเซิร์ฟเวอร์

## สิทธิ์และ Workflow

ผู้ดูแลระบบ: ทุกโมดูลรวมบัญชี สิทธิ์ และตั้งค่า

บรรณาธิการ: จัดการและเผยแพร่เนื้อหาทั้งหมด ไม่มีสิทธิ์จัดการบัญชีและค่าระบบ

ผู้เขียน: สร้างและแก้ไขร่างของตนเอง ไม่มีสิทธิ์เผยแพร่หรือตั้งเวลา; ข่าวที่เผยแพร่แล้วให้บรรณาธิการแก้ไข

สถานะ: ร่าง → เผยแพร่ทันทีหรือรอตั้งเวลา → เผยแพร่ → เก็บเข้าคลัง; ยกเลิกเผยแพร่กลับร่างได้ บันทึกทุกการเปลี่ยนสถานะ

ไม่เพิ่มสถานะรออนุมัติหลายขั้นในระยะแรก

## User Flow

- ผู้อ่าน: หน้าแรก → รายการข่าว → กรอง → รายละเอียด → ดาวน์โหลดหรืออ่านข่าวที่เกี่ยวข้อง
- ผู้เขียน: เข้าระบบ → ข่าว → สร้าง → บันทึกร่าง → ดูตัวอย่าง
- บรรณาธิการ: ข่าวร่าง → ตรวจและแก้ไข → ดูตัวอย่าง → เผยแพร่หรือตั้งเวลา
- จัดการสื่อ: คลังสื่อ → อัปโหลด → ตรวจข้อมูลและคำอธิบายภาพ → เลือกใช้ในข่าว
- กรณีผิดพลาด: แจ้งปัญหาโดยคงข้อมูลที่กรอกและมีวิธีลองใหม่

## หลักฐานก่อนพัฒนา

- ทบทวนหน้ารวมข่าว รายละเอียดข่าว และฟอร์ม Admin ด้วยเนื้อหาตัวอย่าง
- ตรวจหัวข้อไทยยาว ภาพไม่มี คำโปรยยาว และชื่อไฟล์ยาว
- ตรวจการใช้คีย์บอร์ด สถานะโฟกัส และลำดับการอ่าน
- ตรวจทุกบทบาททั้งหน้า UI และสิทธิ์ที่ Backend ในขั้นพัฒนา
- ยืนยันไฟล์โลโก้ หมวดข่าว ข้อมูลหน่วยงาน และผู้รับผิดชอบเนื้อหา
- ยืนยันเซิร์ฟเวอร์ โดเมน พื้นที่จัดเก็บไฟล์ วิธีสำรอง และข้อมูลเก่าที่ต้องย้ายก่อนเลือก Stack
